DEVELOPER INTERFACE

Codex API 接入指南

所有接口使用 JSON。API Key 使用 Authorization: Bearer vnv_...，由服务器命令行生成；不要放在前端、GitHub 仓库或公开日志。接口不允许跨域浏览器调用，但 Codex 的服务端 HTTPS 请求可以访问。

注意：Docker 当前默认可通过 0.0.0.0:6099 接入；请使用 HTTPS 反代后再传输密码或 API Token，不要通过公网明文 HTTP 调用写入接口。

AI 自助操作指南

现在只需向 AI 提供 HTTPS 网站地址、独立 API Token（安全配置为 Secret）和完整操作文档：网站 AI 指引 · GitHub 完整操作手册。请阅读其中的查重、防剧透和字段规则。

1. 生成独立密钥

docker compose exec app python manage.py create-key --name codex

首次生成时会显示密钥一次。可通过 list-keys 查看元数据、revoke-key KEY_ID 撤销。

2. API 基础路径

https://你的域名/api/v1 · OpenAPI JSON

GET /games · POST /games · PATCH /games/{id}

GET /chapters?game_id={id} · POST /chapters · POST /chapters/{id}/unlock

GET /entries?chapter_id={id} · POST /entries · PATCH /entries/{id}

GET /characters?game_id={id} · POST /characters

GET /links?game_id={id} · POST /links

GET /theories?chapter_id={id} · POST /theories

DELETE /{resource}/{id} · GET /health

3. Codex 写入示例

curl -X POST 'https://archive.example.com/api/v1/games' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"title":"海猫鸣泣之时","genre":"悬疑推理","description":"个人阅读档案"}'

先创建游戏，获得 game.id；再创建章节并取得 chapter.id；最后向该章节写入事件、证据或推理。详见仓库的 docs/CODEX_INTEGRATION.md。
